# الصِّدّيق — Owner Vault / خزنة المالك

## الهدف

إنشاء أقوى طبقة عملية لحساب مدير النظام بدون الاعتماد على إخفاء الواجهة.
كود JavaScript الذي يُرسل للمتصفح لا يمكن جعله سريًا بالكامل؛ لذلك الحماية الحقيقية للبيانات والعمليات يجب أن تكون في Auth + RLS + RPC/Edge Functions.

## الطبقات المعتمدة

1. **Passkey / WebAuthn للمالك**
   - بصمة الجهاز أو Face ID أو Windows Hello أو مفتاح أمني.
   - المفتاح الخاص يبقى على جهاز/مدير مفاتيح المالك.
   - Supabase يحتفظ بالمفتاح العام فقط.

2. **عامل ثانٍ AAL2 للعمليات الحرجة**
   - نستخدم MFA مستقرًا (TOTP) للترقية إلى `aal2`.
   - لاحقًا نربط RPCs الحساسة بسياسة تتطلب مدير نظام نشط + `aal2`.

3. **RLS إلزامي على كل جدول مكشوف**
   - لا نعتمد على React لحماية البيانات.
   - كل SELECT/INSERT/UPDATE/DELETE يمر بسياسة قاعدة البيانات.

4. **RPC / SECURITY DEFINER بأقل صلاحية**
   - سحب EXECUTE من `anon` لأي دالة ليست عامة عمدًا.
   - الدوال الحساسة تتحقق داخليًا من المستخدم والدور ومستوى التحقق.
   - تثبيت `search_path` لكل دالة ذات صلاحيات مرتفعة.

5. **Step-up للمالك**
   - قبل إجراءات مثل تعطيل مستخدم، ربط مشرف، تعديل اشتراك، أو تغيير صلاحيات: يطلب النظام تحققًا قويًا حديثًا.
   - لا يعتمد القرار النهائي على متغير داخل المتصفح.

6. **جلسة وخروج طارئ**
   - تقليل عمر التوكنات في المناطق الحساسة.
   - دعم إبطال الجلسات عند الاشتباه.
   - عدم حفظ كلمات مرور أو أسرار مالك في Local Storage.

## حالة التنفيذ في v2.1

- تم تفعيل دعم Passkey في Supabase JS client (ميزة تجريبية من Supabase).
- تمت إضافة زر دخول Passkey في صفحة الدخول.
- تمت إضافة صفحة "خزنة المالك" لمدير النظام لتسجيل/عرض/إلغاء Passkeys.
- **لم يتم فرض البصمة على الإنتاج بعد** حتى لا يتم قفل حساب المدير قبل تفعيل Passkeys وتسجيل مفتاحين موثوقين وإصلاح RLS/RPCs.

## ترتيب التفعيل الآمن

1. إصلاح RLS المكشوف وسياسات RPC/Views.
2. تفعيل Passkeys في Supabase Auth مع RP ID ثابت ودومين الإنتاج الصحيح.
3. تسجيل Passkey أساسي للمالك.
4. تسجيل Passkey احتياطي على جهاز/مفتاح مختلف.
5. تفعيل TOTP احتياطي/عامل ثانٍ.
6. اختبار تسجيل الدخول والخروج والاستعادة.
7. فقط بعد نجاح ذلك: فرض Owner Vault على `/system-admin` والعمليات الحساسة في قاعدة البيانات.

## مبدأ مهم

"بصمة المالك" لا تعني أن التطبيق يحصل على صورة البصمة. WebAuthn يجعل الجهاز يثبت امتلاكه لمفتاح خاص بعد تحقق بيومتري محلي؛ التطبيق والخادم لا يستلمان البصمة نفسها.
